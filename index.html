Research

The layer between intelligent software and the systems that run it: OS scheduling, runtime adaptation, and resource management for concurrent LLM inference.

In progress

LLMFlow: adaptive runtime control for concurrent edge LLM inference

A closed-loop scheduling framework, orchestrated as a LangGraph state machine, that watches three concurrently served edge LLMs (Llama 3.2 1B, Gemma 3 1B, Granite3.1-moe:1b, running on a MacBook M1) and intervenes through existing OS interfaces, renice, cpulimit, and taskpolicy, rather than modifying the kernel.

The core question: should a scheduling policy just react to telemetry, learn from past rewards, or learn conditioned on current system state? I compare a stateless LLM agent, a non-contextual epsilon-greedy bandit, and a contextual LinUCB bandit. LinUCB, tuned for mean latency, comes out ahead on both mean and tail latency, though which model benefits most depends on the workload and the objective chosen.

LangGraphOllamaPythonmacOSContextual bandits
observe decide act evaluate

The same monitoring, diagnosis, and enforcement pipeline runs under all three decision policies, so differences in outcome trace back to the policy alone.

iGenOrch

Intelligent orchestration framework for multi-model LLM inference on edge platforms. With Faiza Akram, Gabriella Dunne, Katherine Williams, Kaleb Love, Dr. Asad Waqar Malik, and Samee U. Khan.

Modifies the Linux CFS scheduler directly, in a custom Raspberry Pi 4 kernel, extending the process descriptor with LLM-aware metadata like queue depth and processing latency. A rule-based policy adjusts CPU affinity, priority, and batch size, and holds latency lower and more stable than default CFS as batch size grows.
